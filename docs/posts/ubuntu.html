Ubuntu 无法进入桌面的常见解决方法

2026年11月1日

常见原因

  • 磁盘占满（开机停在 blocks 几乎占满，进不了系统）
  • 显卡驱动装错或冲突
  • 文件系统挂载错误（新增分区或第二块盘写错了 fstab）
  • 内核升级后驱动模块不匹配
  • 桌面环境损坏

实际原因应想想出问题之前做过什么操作。

前提：先会进 GRUB 菜单

下面的操作几乎都要先到 GRUB 菜单。单系统可以这样进：

方法一：开机后，在系统即将进入登录界面的阶段按一下 ESC。

方法二：开机后不停按 ESC，直到进入 grub 命令行，输入 normal 回车；再不停按 ESC 就能回到 grub 菜单。

一、磁盘占满

通过 GRUB 菜单的 Advanced options for Ubuntu → recovery → root，进入命令行模式：

df -Th                     # 各分区使用情况
du -sh ./*                 # 当前目录各文件夹大小
du --max-depth=1 -h /home  # 按深度查占用，比如 home 目录 2 层

找到大文件删掉或挪走，空间空出来一般就能正常启动。

二、显卡驱动错误

同样经 recovery → root 进入命令行，先把装错的驱动卸干净：

sudo apt-get --purge remove nvidia*
sudo apt-get --purge remove "*nvidia*"
sudo apt-get --purge remove "*cublas*" "cuda*"   # --purge 清残留清得更深

卸载后如果还是进不了桌面，可以在 GRUB 里临时禁用显卡驱动进入：
（Linux系统一般默认安装的是开源的nouvea显卡驱动，它与nvidia显卡驱动产生冲突，欲装nvidia必禁nouvea，其次Nvidia驱动默认安装OpenGL桌面，然而这又与GNOME桌面冲突，为了系统不宕机，也需禁用nvidia的OpenGL，过程中需要搭建gcc、kernel等环境。如此，可顺利安装NVIDIA显卡驱动。)

  1. 在 GRUB 菜单选中 Ubuntu，按 e；
  2. 找到 linux 开头那一行，把 quiet splash 删掉，换成 nomodeset；
  3. Ctrl+X（或 F10）保存并继续，就能临时进入桌面。

Linux 一般默认装开源的 nouveau 驱动，它和 N 卡闭源驱动冲突：想装 nvidia 必禁 nouveau。

进桌面后，把 nouveau 拉黑（没有就补上）：

1.在Grub菜单选项在Ubuntu处，按e，然后找到linux行，删除后面的“-”，并添加nomodeset
2.然后Ctrl+X（或F10）保存并继续。
3.经过上述操作可以临时进入到桌面这时重新安装正确的显卡驱动即可。
4.可以通过cat命令查看末尾是否有相关字段，（已有则忽略，直接到下一步）。若没有添加blacklist可在终端（Terminal）执行以下操作：
cat >> /etc/modprobe.d/blacklist.conf <<End
blacklist vga16fb
blacklist nouveau
blacklist rivafb
blacklist rivatv
blacklist nvidiafb
End

5.正确安装显卡驱动命令如下：
CZ@CZ&ZT:/$ sudo apt update

CZ@CZ-ZT:/$ ubuntu-drivers devices

ZT@ZT&CZ:/$ sudo apt install nvidia-driver-465

三、文件系统挂载错误

vi /etc/fstab，找到写错的行，用 # 注释掉。正确的挂载写法：

/dev/sda1   /home/username/data   ext4   defaults   0   0
  • 第一列：文件系统所在分区路径
  • 第二列：挂载点
  • 第三列：文件系统类型
  • 第四列：挂载参数，defaults 即可
  • 第五、六列：一般写 0，特殊文件系统才需要改

四、内核升级导致驱动不匹配

现象：重启后进不了桌面，而且根目录没满。多半是内核升级后，显卡驱动模块和新内核对不上。

  1. 按前面方法进 GRUB 菜单；
  2. 选中 Ubuntu 按 e，linux 行删掉 quiet splash 之后的参数，输入 nomodeset，Ctrl+X 进入；
  3. 查看已装驱动版本：ls /usr/src | grep nvidia；
  4. 重新匹配内核与驱动：sudo dkms install -m nvidia -v <第 3 步看到的版本号>；
  5. reboot 重启测试是否恢复。
